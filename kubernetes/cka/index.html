03 · Mac mini Setup

Docker Desktop + kind：先固定可重建環境

建議：Docker Desktop 約 6–8 GB RAM。Apple Silicon / Intel 都可使用 multi-arch kind image。
brew install kubectl kind helm
uname -m
cat > kind.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
- role: worker
- role: worker
EOF
kind create cluster --name cka \
  --image kindest/node:v1.35.8@sha256:07b2536e30b803ed61d1677a79df6115f798ce64c80f9e22f6ed45afd09323c0 \
  --config kind.yaml
kubectl get nodes -o wide
環境誠實性：kind Node 是 container，不等同完整 systemd Linux VM；不能拿它假裝完成真 kubelet package upgrade 或 production HA。

05 · Simulator / Linux VM Required

Mac kind 做不到的，這三組一定另外補

必補 A｜kubeadm Cluster Lifecycle / Upgrade

在真正 Linux control plane + worker 走過 drain → kubeadm upgrade → kubelet package/service → uncordon。版本依題目指定，不死背 patch version。

kubectl drain <node> --ignore-daemonsets
kubeadm upgrade plan
kubeadm upgrade apply v1.35.x
systemctl daemon-reload
systemctl restart kubelet
kubectl uncordon <node>

必補 B｜Highly Available Control Plane

能說清楚 stable controlPlaneEndpoint / load balancer、多 kube-apiserver、controller/scheduler leader election，以及 stacked vs external etcd。HA 不是「多幾台 worker」。

kubectl get nodes
kubectl get pods -n kube-system -o wide
kubectl get leases -n kube-system

必補 C｜真 kubelet / systemd troubleshooting

kubectl get nodes
kubectl describe node <node>
ssh <node>
systemctl status kubelet
journalctl -u kubelet --no-pager -n 100
crictl ps -a
# 修正後
systemctl restart kubelet
kubectl get nodes
紀律：先收 evidence，再改一個原因，最後回 kubectl 驗證。
