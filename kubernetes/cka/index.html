03 · Mac mini Setup

Docker Desktop + kind：先把「每天都能重建」的環境固定

建議：Docker Desktop 分配約 6–8 GB RAM。Apple Silicon / Intel 都能使用 kind multi-arch image。這套環境非常適合 RBAC、workload、service、storage object 與多數 troubleshooting。
brew install kubectl kind helm
uname -m
cat > kind.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
- role: worker
- role: worker
EOF
kind create cluster --name cka \
  --image kindest/node:v1.35.8@sha256:07b2536e30b803ed61d1677a79df6115f798ce64c80f9e22f6ed45afd09323c0 \
  --config kind.yaml
kubectl get nodes -o wide
kubectl cluster-info --context kind-cka
一定要接受一件事：kind Node 是 container，不是完整 systemd Linux VM。你可以看 kubeadm/static manifests，但不能把它當作真正 kubelet systemd、multi-control-plane HA、OS package upgrade 的等價環境。

04 · 50 Hands-on Labs

05 · Simulator / Linux VM Required

Mac kind 做不到的，不裝懂：這 3 組一定要另外補

必補 A｜kubeadm Cluster Lifecycle / Upgrade

目標：在真正 Linux control plane + worker 上走過 kubeadm upgrade 流程，知道版本 skew、drain、upgrade node、uncordon 的順序。

# control plane（實際版本依題目指定）
kubectl drain <node> --ignore-daemonsets
kubeadm upgrade plan
kubeadm upgrade apply v1.35.x
# 升級 kubelet/kubectl 套件後
systemctl daemon-reload
systemctl restart kubelet
kubectl uncordon <node>

# worker 常見流程
kubectl drain <worker> --ignore-daemonsets
kubeadm upgrade node
# upgrade kubelet package
systemctl restart kubelet
kubectl uncordon <worker>
考場陷阱：題目指定哪台 node、哪個 target version、哪個 package manager，就照題目；不要照背固定 patch version。

必補 B｜Highly Available Control Plane 心智模型

你要能說清楚：多個 kube-apiserver 前面通常需要穩定 endpoint/load balancer；controller-manager/scheduler 會 leader election；etcd 可以 stacked 或 external。HA 不是「多開幾個 worker」。

kubectl get nodes
kubectl get pods -n kube-system -o wide
kubectl get leases -n kube-system
# 真 HA lab 另外確認 controlPlaneEndpoint、API LB/virtual IP、etcd members
能回答才算過：如果第一台 control-plane 掛掉，client 為什麼仍能透過同一個 API endpoint 存取其他 apiserver？

必補 C｜真 Node / kubelet / component troubleshooting

目標：至少在 Linux VM / Killer.sh 做過一次 kubelet stop、錯誤 config、certificate/runtime/CNI 線索的排錯。這是 kind 最不能取代的一段。

kubectl get nodes
kubectl describe node <node>
ssh <node>
systemctl status kubelet
journalctl -u kubelet --no-pager -n 100
crictl ps -a
crictl logs <container-id>
# 修正後
systemctl restart kubelet
kubectl get nodes
排錯紀律：先收集 evidence 再改設定；一次改一個原因，修完一定回到 kubectl 驗證狀態。
