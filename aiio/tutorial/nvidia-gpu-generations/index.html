GPU Generations · NCA-AIIO Tutorial

A100 → H100/H200 → B200 → B300 → Rubin

從 GPU 世代、HBM、Tensor Core、NVLink 一路連到 MIG、nvidia-smi、SMBPBI、DGX/HGX 與 NCA-AIIO 情境題。

考試讀法：不要死背 CUDA Core 數量。先記「架構 → 代表技術 → Memory → Interconnect → 主要 workload」，再判斷題目是在考 Compute、Memory、Scale-up、Scale-out、Operations 還是 Facility。

A100 — Ampere：TF32 與 MIG

A
A100 = Ampere

80GB 版本採 HBM2e；A100 把 TF32、第三代 Tensor Core 與 MIG 帶入主流資料中心 GPU 使用情境。

NCA-AIIO 辨識點

題目看到「把一張 GPU 隔離切給多個 workload」→ MIG。注意 MIG 不是 H100 才有，A100 就已支援。

H100 / H200 — Hopper：Transformer Engine 與 FP8

H100

Hopper、80GB HBM3、3.35TB/s、第四代 Tensor Core、Transformer Engine、FP8、NVLink 4 900GB/s。

H200

仍是 Hopper，但把 HBM 提升到 141GB HBM3e / 4.8TB/s，特別有利於大型模型、KV cache 與 memory-bound inference。

B200 — Blackwell：NVFP4 與大規模 GenAI

關鍵不是只看「更快」：Blackwell 強調低精度 AI compute（如 NVFP4）、第五代 NVLink 與 rack-scale AI infrastructure。DGX B200 的 8 顆 GPU 合計 1,440GB HBM3e、64TB/s，因此可快速推得每 GPU 180GB、約 8TB/s。

B300 — Blackwell Ultra：把 Memory 與 Attention 再往上推

最高 288GB HBM3e

較大的 on-package memory 可容納更大的模型、更多 KV cache、更長 context 與更高 concurrent users。

15 PFLOPS dense NVFP4

Blackwell Ultra 特別強化 attention layer 與 agentic / reasoning 型 inference。不要把 B300 誤背成全新的非 Blackwell 架構。

Rubin — 最新主線：HBM4 + NVLink 6 + Agentic AI

288GB HBM4

容量支援模型常駐、long context、KV cache 與高 concurrency。

22 TB/s

Memory bandwidth 約為 Blackwell / Blackwell Ultra 的 2.8 倍等級，對 decode 階段特別重要。

NVLink 6

每 GPU 3.6TB/s scale-up bandwidth，較 Blackwell NVLink 5 再翻倍。

名稱要分清：Rubin = GPU architecture / GPU；Vera = CPU；Vera Rubin = CPU + GPU 平台。Vera Rubin NVL72 則是 rack-scale system，不是一顆 GPU。

3. GPU、HGX、DGX、NVL72 不要混

B200 / Rubin = GPU HGX B200 / HGX Rubin NVL8 = GPU baseboard / platform DGX B200 / DGX Rubin NVL8 = NVIDIA 完整系統 GB200 NVL72 / Vera Rubin NVL72 = Rack-scale AI system
答題技巧：題目若問「GPU」就不要選 DGX；題目若問 turnkey / complete NVIDIA AI system，DGX 才比較像答案；題目若強調 72-GPU rack-scale domain，想到 NVL72。

4. MIG：不是「-mig 1 = 切一個」

sudo nvidia-smi -i 0 -mig 1 裡的 1 是 Enable，不是 instance 數量。
# Step 1：開啟 MIG mode
sudo nvidia-smi -i 0 -mig 1

# Step 2：例：H100 80GB 建 5 個 1g.10gb GPU Instance，並同時建 Compute Instance
sudo nvidia-smi mig -i 0 \
  -cgi 1g.10gb,1g.10gb,1g.10gb,1g.10gb,1g.10gb \
  -C

# 確認
nvidia-smi -L
sudo nvidia-smi mig -lgi
sudo nvidia-smi mig -lci

Max instances ≈ min( floor(7 / compute_slices), floor(8 / memory_slices) )

6. SMBPBI：BMC 怎麼 OOB 管 NVIDIA GPU

SMBPBI = SMBus Post-Box Interface。它是 NVIDIA GPU 的 out-of-band 管理介面之一，跑在 SMBus 上，可讓 BMC 在 Host OS / NVIDIA driver 不可用時仍取得部分 GPU telemetry / status，並進行支援的管理操作。

In-band Linux → NVIDIA Driver → NVML / nvidia-smi / DCGM → GPU Out-of-band BMC → SMBus → SMBPBI → GPU 對外管理 BMC → Redfish / IPMI
SMBus

Transport / electrical bus。

SMBPBI

跑在 SMBus 上的 NVIDIA GPU management interface / protocol。

與其他協定分清：PMBus 常見於 PSU / VR power；MCTP 是 management transport；PLDM 是平台管理資料模型 / command set；SMBPBI 則是 NVIDIA GPU OOB 管理路徑之一。

7. PFLOPS 是什麼？

FLOPS = Floating-Point Operations Per Second，表示每秒能做多少次浮點運算。

1 TFLOPS = 10¹² FLOPS
1 PFLOPS = 10¹⁵ FLOPS = 1,000 TFLOPS

例如 50 PFLOPS NVFP4，代表在該精度與官方定義條件下，理論 peak throughput 可達每秒 50 × 10¹⁵ 次浮點運算。

不要直接跨 precision 比 FLOPS：50 PFLOPS FP4 不能單純說一定是 5 PFLOPS FP8 的「10 倍實際 AI 效能」。還要看 precision、dense/sparse、模型形態、memory bandwidth、batch、kernel efficiency 等。

8. Scale-up / Scale-out：NVLink 不等於 InfiniBand

Scale-up

同一個高速 GPU domain 內擴張，重點是 GPU ↔ GPU 低延遲、高頻寬。

關鍵字：NVLink、NVSwitch。

Scale-out

跨 node / rack 擴張，需要高速 data-center network。

關鍵字：InfiniBand、Spectrum-X Ethernet、RDMA。

GPU ↔ GPU NVLink / NVSwitch = scale-up Node ↔ Node / Rack ↔ Rack InfiniBand / Ethernet = scale-out

Q1. Which GPU is based on the NVIDIA Ampere architecture?
A. H100　B. A100　C. B200　D. Rubin
看答案
B. A100。A100 = Ampere；H100/H200 = Hopper；B200 = Blackwell；B300 = Blackwell Ultra；Rubin = Rubin。
Q2. Which technology partitions one physical GPU into isolated GPU instances?
A. NVLink　B. MIG　C. InfiniBand　D. TensorRT
看答案
B. MIG。MIG 是 GPU resource partitioning；NVLink 是 GPU interconnect。
Q3. An H100 command uses nvidia-smi -i 0 -mig 1. What does the final 1 mean?
A. Create one instance　B. Use 1GB memory　C. Enable MIG mode　D. Select GPU 1
看答案
C. Enable MIG mode。建立 instance 要另外使用 nvidia-smi mig -cgi ... -C。
Q4. Which statement about H200 is correct?
A. It uses Blackwell　B. It is Hopper with larger/faster HBM than H100　C. It has no Tensor Cores　D. It is a DPU
看答案
B。H200 仍是 Hopper，核心差異之一是 141GB HBM3e / 4.8TB/s。
Q5. Which statement best distinguishes B300 from B200?
A. B300 is Hopper　B. B300 removes NVLink　C. B300 is Blackwell Ultra with up to 288GB HBM3e　D. B300 is a CPU
看答案
C。B300 / Blackwell Ultra 強化 memory capacity、attention 與 reasoning workload。
Q6. Which memory technology is a key Rubin GPU change?
A. DDR4　B. GDDR5　C. HBM2e　D. HBM4
看答案
D. HBM4。Rubin 最高 288GB HBM4、22TB/s。
Q7. Which interconnect is primarily used for high-bandwidth GPU-to-GPU scale-up?
A. SATA　B. NVLink　C. IPMI　D. USB
看答案
B. NVLink。跨 node / rack 的 scale-out 則常見 InfiniBand 或高速 Ethernet。
Q8. A long-context LLM inference service is bottlenecked by KV cache and token generation. Which hardware characteristics matter most?
A. Display outputs　B. GPU memory capacity and bandwidth　C. More USB ports　D. BMC flash size
看答案
B。Long context 與高 concurrency 會增加 KV cache；decode 也高度依賴 memory bandwidth。
Q9. Which NVIDIA tool is intended for data-center GPU monitoring, health, and diagnostics?
A. DCGM　B. CUDA compiler　C. NVLink　D. NCCL only
看答案
A. DCGM。nvidia-smi 適合基本 CLI；DCGM 更偏 data-center operations。
Q10. What is SMBPBI used for in an AI server?
A. Image rendering　B. GPU OOB management over SMBus　C. LLM tokenization　D. Kubernetes scheduling
看答案
B。BMC 可透過 SMBus / SMBPBI 取得支援的 GPU OOB telemetry / management information。
Q11. Which statement correctly describes Vera Rubin?
A. Vera is the GPU and Rubin is the NIC　B. Rubin is GPU; Vera is CPU; Vera Rubin is the platform　C. Vera Rubin is only a software library　D. Rubin is an A100 MIG profile
看答案
B。另外 Vera Rubin NVL72 是 rack-scale system。
Q12. 1 PFLOPS equals:
A. 10⁶ FLOPS　B. 10⁹ FLOPS　C. 10¹² FLOPS　D. 10¹⁵ FLOPS
看答案
D。1 PFLOPS = 1,000 TFLOPS = 10¹⁵ FLOPS。
