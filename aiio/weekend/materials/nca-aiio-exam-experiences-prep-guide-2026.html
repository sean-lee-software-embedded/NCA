研究說明

研究方法與判讀原則

本頁不是將搜尋結果照單全收，而是依證據品質分成三層：官方規則用來確認考試形式與監考要求；可識別作者與背景的第一手分享用來理解準備方式與題型感受；課程或題庫銷售頁則保留商業利益關係標示。

官方可驗證事實

最高優先

NVIDIA 認證頁、官方 Study Guide 與 Certiverse 支援文件。考試費用、時間、題數、設備與房間規則以這一層為準。

個人經驗

可參考，不可泛化

通過者的準備時數、難度感受、高頻主題和臨場狀況。作者背景差異很大，不能把單一案例當成每個人的結果。

商業性內容

有用但需交叉核對

免費影片、Udemy、ExamPro、bootcamp 或付費題庫。內容可能有價值，但創作者可能同時銷售相關產品。

高風險資訊

不採用為證據

Synthesis

網路心得共識

  1. 範圍廣、辨識題多：重點多在元件用途、責任邊界、技術差異和情境選型，不是深入寫程式。
  2. Infrastructure 不能略讀：AI Infrastructure 佔 40%，只讀 AI／ML 基礎和 CUDA 不足以安全應考。
  3. 官方課程與 Suggested Readings 是主幹：第三方影片適合建立輪廓，技術細節仍應回到 NVIDIA 文件。
  4. 錯題檢討比盲目刷題重要：多位作者都採用「模擬題找弱點 → 查文件 → 建比較表 → 再測」循環。
  5. 題目需要快速辨識：50 題只有 60 分鐘，知道元件責任的人通常能快速排除；不熟的題目不適合長時間猜想。
  6. 線上監考本身是一項風險：設備權限、VPN、額外螢幕、房間物品、證件姓名與網路穩定都可能拖延或中斷。
不能泛化的心得：有人覺得考試很容易或很快完成，只能代表其背景與當時題組。NVIDIA 並未承諾每位考生會得到同等難度，也未公開可用來推導及格所需答對題數的固定門檻。
Exam Focus

高優先主題

軟體堆疊能區分 CUDA、cuDNN、TensorRT、Triton、NIM、NeMo、RAPIDS、NCCL、NGC。常見干擾方式是把模型最佳化、模型服務、開發框架與分散式通訊互換。
Training／InferenceTraining 通常偏 throughput、大批次、顯存與 GPU 間高速通訊；inference 常偏 latency、併發、動態批次、模型最佳化與 serving efficiency。這是典型傾向，不是絕對規則。
資源共享MIG 是硬體層級切割與隔離；time-slicing 是輪流共享，不具有同等記憶體與故障隔離；vGPU 用於虛擬化環境的 GPU 資源配置。
Direct 技術GPUDirect Storage 是 GPU ↔ 儲存；GPUDirect RDMA 是 GPU ↔ NIC／第三方 PCIe 裝置；CUDA P2P 是 GPU ↔ GPU。先找資料路徑兩端再作答。
維運工具nvidia-smi 做單機即時檢查；DCGM 做 GPU 遙測、健康與診斷；DCGM Exporter 提供 Prometheus 指標；Base Command Manager 管理叢集；GPU Operator 部署 Kubernetes GPU 軟體元件。
排程與擴縮Slurm 偏批次與 HPC／訓練工作；Kubernetes 偏容器、服務與宣告式管理。GPU Operator 不等於 HPA，也不等於 Cluster Autoscaler。
網路InfiniBand、Ethernet／RoCE、NVLink、NVSwitch、ConnectX、NCCL collective、scale-up／scale-out，以及 compute、storage、in-band、out-of-band 網路分離。
資料中心PUE、TDP、rack density、電力容量、空氣冷卻與液冷。液冷改善熱移除能力，但不代表 GPU 不耗電。
DPUBlueField DPU 的核心價值可記成 offload、accelerate、isolate：卸載主機 CPU 的基礎設施服務、加速網路／儲存／安全處理、隔離控制面。
DGX／SuperPOD理解 DGX H100 系統角色、NVLink／NVSwitch 的節點內位置、ConnectX 的節點間連線、BMC／OOB 管理與 SuperPOD reference architecture。
Study Method

準備方法：從錯題建立能力

1. 先用官方 Blueprint 建目錄

不要從第三方題庫反推考綱。先建立 38／40／22 的學習清單，再把每次錯題掛回對應 domain 與 objective。Infrastructure 是最大領域，若目前最弱，更應優先補足。

2. 為每題記錄錯誤原因

  • 不知道名詞。
  • 混淆兩個 NVIDIA 產品。
  • 不清楚資料路徑。
  • 不清楚工具責任邊界。
  • 硬體規格或數字記錯。
  • 沒看清楚題目要改善 latency、throughput、isolation、availability 或 scalability。
  • 英文關鍵字判讀錯誤。

3. 至少建立八張比較表

  1. CPU vs GPU
  2. Training vs inference
  3. CUDA vs cuDNN vs TensorRT vs Triton
  4. MIG vs time-slicing vs vGPU
  5. DCGM vs BCM vs GPU Operator
  6. Slurm vs Kubernetes
  7. GDS vs GPUDirect RDMA vs CUDA P2P
  8. NVLink vs NVSwitch vs InfiniBand／RoCE

4. 配合少量實作

至少實際看過 nvidia-smi、GPU utilization／memory／temperature／power、Docker 與 NVIDIA Container Toolkit、Kubernetes 的 nvidia.com/gpu，以及 DCGM Exporter 指標。沒有 DGX 也可以使用雲端 GPU、官方輸出範例或模擬環境。

模擬建議：做完一回後，不只檢討答錯題；猜對、理由說不清楚或排除過程錯誤的題目也要算入弱點。建議連續兩回全新 50 題模擬都達到 85% 以上，且三個 domain 沒有明顯短板，再安排正式考試。85% 是準備安全緩衝，不是 NVIDIA 公開及格線。
Action Plan

7 天衝刺計畫

第 1 天

考綱與基準測驗

讀官方考綱；不看答案完成一回 50 題；把錯題按 domain 與錯誤原因分類。

第 2 天

Essential AI Knowledge

複習軟體堆疊、GPU vs CPU、training vs inference、AI lifecycle 與 NVIDIA 產業方案；晚上集中練 Essential。

第 3 天

Infrastructure：硬體與設施

DGX／HGX、NVLink／NVSwitch、GPU sizing、記憶體、PUE、TDP、電力、機櫃、冷卻與 cloud vs on-premises。

第 4 天

Infrastructure：網路與儲存

InfiniBand、RoCE、Ethernet、ConnectX、BlueField、GDS、RDMA、P2P、scale-up／scale-out 與網路分離。

第 5 天

AI Operations

DCGM、Exporter、BCM、GPU Operator、Kubernetes、Slurm、MIG、time-slicing、vGPU 與 GPU 健康監控。

第 6 天

兩回完整模擬

上午 50 題／60 分鐘，完整檢討；下午或晚上再做一回。若同類錯題重複，停止盲刷並回到官方文件。

第 7 天

輕量複習與設備檢查

只看比較表與錯題；不再大量吸收新資料；完成 Certiverse 相容性測試、整理房間並提前休息。

Certiverse

線上監考注意事項

考前幾天

考試當天

  • 至少提前 15 分鐘啟動流程；正式計時在監考員完成 pre-flight 並釋放考試後開始。
  • 重新開機並關閉所有不必要程式；非 SEB 考試可能檢查 Task Manager、System Tray 或 macOS Activity Monitor。
  • 清空桌面與手臂可及範圍；移除紙張、書籍、手機、智慧手錶與其他電子裝置。
  • 額外螢幕必須拔除，並移走或覆蓋；考試房間要安靜、獨立且照明充足。
  • 監考員會核對證件並要求完整掃描房間與桌面。

考試進行中

  • 保持頭與肩膀在鏡頭內，不要離開座位。
  • 不要念題、喃喃自語、用嘴形讀題或長時間看向螢幕外。
  • 卡住時先回答並標記，最後從 review page 回看。
  • 若斷線，官方表示進度會自動保存，最多有 30 分鐘重新連線；超過後將依已完成答案自動提交評分。

考後

Certiverse 說明指出，通過後可能需要最多 72 小時驗證答案，完成後才會以 email 寄出成績報告、證書與 badge。若超過 72 小時仍未收到，再向 exam organization 或 Certiverse 支援查詢。

Source Safety

高風險資訊與不採用內容

不要直接相信

  • 聲稱 100% actual exam questions。
  • 宣稱必然通過或「全部原題」。
  • 沒有作者、日期與技術來源。
  • 只販售 VCE／PDF dump，沒有教學或勘誤。
  • 答案與 NVIDIA 官方文件互相矛盾。

相對可靠

  • NVIDIA 官方 certification page 與 Study Guide。
  • NVIDIA 產品與技術文件。
  • Certiverse 官方監考規則。
  • 清楚交代作者背景、準備時數與限制的心得。
  • 明確說明是原創練習題並附來源的社群教材。

付費課程、bootcamp、Udemy、ExamPro 或帶折扣碼文章不一定錯，但應標為商業性內容並回查官方文件。LinkedIn 只有證書照片、沒有方法與細節的貼文，只能證明作者自稱通過，不能證明其準備建議有效。
