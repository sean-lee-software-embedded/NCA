高 GPU 使用率搭配低顯示記憶體占用，通常表示核心計算活動繁忙，但容量仍有餘裕；這不能單獨證明 ECC 故障，也不能以記憶體未滿推論 GPU 閒置。

核對來源：[S15]

QUESTION 082AI Operations · Objective 3.4

管理員要把支援 MIG 的單張 GPU 分割給多個彼此隔離、資源需求固定的推論服務。MIG 的主要優點為何？

正確答案：B — 建立具隔離運算與記憶體資源的硬體分割執行個體

MIG 可將支援的 GPU 劃分為多個具隔離運算與記憶體資源的 GPU 執行個體，適合多租戶或多服務的可預測資源配置；它不會讓每個分割區取得整卡全部資源。

核對來源：[S16] [S5] [S18]

QUESTION 083AI Operations · Objective 3.2

某批次訓練工作只應排到已安裝特定 GPU 驅動且通過驗證的節點。哪種 Kubernetes 方法最直接且可稽核？

正確答案：C — 為合格節點加上標籤，並在工作負載設定 nodeSelector 或 node affinity

節點標籤搭配 nodeSelector 或 node affinity，能在排程階段明確約束工作負載只落到符合條件的節點。提高 CPU 限制或 privileged 權限都不會讓排程器自動辨識指定驅動條件。

QUESTION 084AI Operations · Objective 3.1

DCGM 健康檢查持續回報某張 GPU 有不可修正的記憶體錯誤。維運人員的最佳第一步為何？

正確答案：D — 隔離或封鎖該 GPU 所在節點以避免新工作排入，保留診斷資訊並依程序處理

不可修正錯誤可能影響工作可靠性。先停止新工作進入受影響資源、保存遙測與事件資料，再依維修或更換程序處理，可降低風險並保留根因分析證據。

QUESTION 085AI Operations · Objective 3.3

團隊想辨識 GPU 是否因溫度過高而降頻。除了溫度外，最應關聯觀察哪一類指標？

正確答案：A — SM 時脈與節流原因

判斷熱節流需要把溫度、SM 時脈及節流原因一起觀察；若高溫期間時脈下降且出現熱相關節流原因，證據比單看溫度更完整。

QUESTION 086AI Operations · Objective 3.2

某節點提供四個 MIG 裝置資源。工作負載宣告需要一個相符的 MIG 延伸資源。排程器主要依據什麼判斷是否可排入？

正確答案：B — 節點尚未配置的該類 MIG 延伸資源數量是否足夠

MIG 裝置可透過 device plugin 以延伸資源呈現；排程器根據 Pod 宣告的資源需求與節點可配置數量進行放置，不會從名稱或映像發布者推斷需求。

QUESTION 087AI Operations · Objective 3.4

企業需要讓多台虛擬機共享實體 GPU，並由管理平台為各 VM 指派受支援的虛擬 GPU 設定檔。應優先採用哪項技術？

正確答案：C — NVIDIA vGPU

NVIDIA vGPU 用於在受支援的虛擬化堆疊中，依 vGPU profile 將實體 GPU 能力配置給多台 VM。直接讓所有 VM 無仲介地存取同一 PCI 位址不是正確的共享方式。

QUESTION 088AI Operations · Objective 3.1

一個 GPU Pod 一直處於 Pending。事件顯示 Insufficient nvidia.com/gpu。首先應檢查什麼？

正確答案：D — 是否有節點公開足夠且未配置的 nvidia.com/gpu 資源，以及 device plugin 是否正常

Insufficient nvidia.com/gpu 是排程資源不足訊息，應先確認節點 capacity/allocatable、既有配置及 device plugin 狀態。Readiness probe 只在 Pod 啟動後影響服務就緒狀態。

QUESTION 089AI Operations · Objective 3.3

兩個模型的 GPU 使用率相近，但模型 A 的 framebuffer memory 使用量持續逼近容量上限。哪個營運風險最值得優先驗證？

正確答案：A — 模型 A 在尖峰或批次增大時可能發生 GPU 記憶體配置失敗

顯示記憶體接近容量上限代表可用餘裕不足，尖峰或 batch 增大可能觸發配置失敗或 OOM。GPU 使用率相近並不能消除容量風險。

QUESTION 090AI Operations · Objective 3.1

維運團隊使用 NVIDIA GPU Operator 管理 Kubernetes GPU 節點。相較於逐台手動安裝元件，其核心營運價值為何？

正確答案：B — 以 Kubernetes 原生方式自動化驅動、device plugin 與監控等 GPU 軟體元件的部署與生命週期

GPU Operator 將 GPU 軟體堆疊的部署與管理自動化，包括驅動、容器工具、device plugin 與監控相關元件；它不會消除應用相依性，也不會取代排程器。

QUESTION 091AI Operations · Objective 3.2

叢集同時有完整 GPU 節點與 MIG 節點。為避免需要整張 GPU 的訓練工作誤排到 MIG 資源池，最佳設計為何？

正確答案：C — 使用明確的資源名稱，並搭配節點標籤、親和性或污點與容忍度區隔資源池

完整 GPU 與 MIG 工作應透過相符的延伸資源宣告，並可用標籤、affinity、taint/toleration 強化資源池隔離。名稱慣例不會影響排程決策。

QUESTION 092AI Operations · Objective 3.3

GPU 功耗已接近設定的功率上限，同時 SM 時脈下降。哪個後續動作最能確認是否為功率限制導致降頻？

正確答案：D — 檢查功率相關節流原因，並把它與功耗及時脈的時間序列對齊

功耗接近上限與時脈下降只是相關現象；再檢查功率節流原因並對齊時間序列，才能建立更直接的診斷依據。

QUESTION 093AI Operations · Objective 3.4

一台 VM 需要一張 GPU 的獨占原生效能與完整裝置控制，不要求與其他 VM 分享該卡。在平台支援下，哪種配置最符合需求？

正確答案：A — PCIe GPU passthrough

PCIe passthrough 將實體 GPU 直接指派給單一 VM，符合獨占與完整裝置存取需求；vGPU profile 著重受控虛擬化配置與共享情境。

QUESTION 094AI Operations · Objective 3.1

GPU Operator 升級後，部分節點不再公開 nvidia.com/gpu。為縮小問題範圍，最合理的檢查順序為何？

正確答案：B — 先看 Operator/ClusterPolicy 與相關 DaemonSet Pod 狀態及事件，再檢查驅動和 device plugin 日誌

GPU 資源是否被公開依賴管理元件、節點驅動及 device plugin。從控制資源狀態與事件開始，再深入相關 Pod 日誌，可由上而下定位升級後的失敗點。

QUESTION 095AI Operations · Objective 3.2

為避免一般工作負載排入昂貴的 GPU 節點，但仍允許經授權的 AI 工作使用這些節點，哪個組合最合適？

正確答案：C — 在 GPU 節點設定 taint，並只讓 AI 工作負載加入相符 toleration，必要時再搭配 affinity

Taint 可排斥未具相符 toleration 的 Pod；授權工作負載加入 toleration 後，可再用 affinity 確保選到 GPU 節點。映像標籤與 hostPID 不會建立排程隔離。

QUESTION 096AI Operations · Objective 3.3

監控面板顯示 GPU utilization 間歇性尖峰，但推論請求延遲穩定。為避免誤判容量不足，下一步最佳做法為何？

瞬時尖峰不必然代表持續容量不足。把 GPU 遙測與工作量及服務層指標對齊，並檢視趨勢與分布，才能判斷尖峰是否影響服務目標。

QUESTION 097AI Operations · Objective 3.4

管理員變更 MIG 幾何配置後，既有工作負載看到的裝置資源與預期不符。哪項操作原則最重要？

正確答案：A — 先排空或停止受影響工作，套用一致的 MIG 配置，確認 device plugin 重新發現並公開資源後再排程

MIG 重配置會改變可用裝置拓撲與對外公開的資源。先控制工作負載、完成一致配置，再驗證 device plugin 與節點 allocatable，可避免執行中資源被破壞或排程資訊過時。

QUESTION 098AI Operations · Objective 3.1

某 GPU 節點可由 nvidia-smi 看見裝置，但 Kubernetes Node 的 allocatable 沒有 nvidia.com/gpu。最可能缺少或異常的元件是什麼？

正確答案：B — NVIDIA device plugin

主機工具能看見 GPU 表示基本裝置與驅動可能可用；Kubernetes 是否公開 nvidia.com/gpu 則依賴 NVIDIA device plugin 向 kubelet 註冊裝置資源。

QUESTION 099AI Operations · Objective 3.2

排程多個 GPU 訓練工作時，團隊希望讓短任務優先，但又避免低優先權任務永遠無法執行。哪個策略最合理？

正確答案：C — 採用佇列與優先權機制，設定配額或公平分享政策，並監控等待時間

優先權可讓重要或短任務先行，但需搭配配額、公平分享或防飢餓政策及等待時間監控。把所有工作設為同級最高優先權無法達成差異化，隱藏資源需求則會破壞排程正確性。

QUESTION 100AI Operations · Objective 3.4

比較 MIG 與 time-slicing 時，哪個敘述最正確？

正確答案：D — MIG 提供硬體層級的分割與資源隔離；time-slicing 讓多個工作輪流使用 GPU，但不等同 MIG 的硬體隔離

MIG 將支援 GPU 切成具有隔離資源的執行個體；time-slicing 是共享存取的排程方式，並不提供與 MIG 相同的硬體資源隔離與固定分割特性。
