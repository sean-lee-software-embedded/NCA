Page 92 / 100Exam Security

正式 Evaluation 有保密與 integrity 規則

AMD Program Agreement 將 evaluation questions、tasks、scoring rubrics、interfaces/workflows 等非公開內容視為 Confidential Information。不得錄影、截圖、散布、使用 brain dump，也不得在 Evaluation 中使用未被允許的外部協助或 generative AI。

因此準備時應使用公開考綱、官方 training、官方 docs 與自己製作的 practice。真正開始 Evaluation 後，若介面明確禁止外部工具，就必須完全依規則作答。

Training Quiz 與正式 Evaluation 要分清楚。你可以把公開學習內容拿來討論；但正式、非公開 exam content 不應複製或外流。
Credential 有效期目前官方定義為 24 months；renewal window 預設在到期前 180 days 開始。

Page 94 / 100Question Strategy

情境題的四步解法

  1. 先判斷 domain：Build / HIP / Port / Library / Profile-Debug？
  2. 找問題類型：Correctness、performance、dependency、multi-GPU、memory？
  3. 選最直接工具：例如 source debugging → ROCgdb，不要選 amd-smi。
  4. 排除絕對化敘述：always、guarantees、maximum occupancy always fastest 通常很可疑。
題目問 “best first step” 時，選 triage 的第一步；不是選最終可能使用的所有工具。
例：PyTorch 不見 AMD GPU，但 rocminfo 也失敗。第一步先查 ROCm/device layer，而不是修改 neural network model。

Page 99 / 100Why Answers

模擬題的「為什麼」：你要會推理，不只記答案

  • Q3：ceil(1000/256)=4；最後一個 block 有多餘 threads，所以 Q27 需要 bounds check。
  • Q7/Q16/Q30：這三題其實都是 Build domain。command-not-found、undefined-reference、CMake dependency 要先在 toolchain/build 層解。
  • Q11/Q22：memory-bound + coalescing 是一組概念；相鄰 threads 的連續 global access 通常更有效率。
  • Q13/Q18：occupancy 受 resources 影響，但它只是指標；最大 occupancy 不保證最快。
  • Q15/Q24/Q25：debugger 與 profiler 要分清楚。ROCgdb 找程式 correctness/source issue；profiler 找時間與 resource bottleneck。
  • Q19/Q28：兩題都提醒「方便的 memory model 仍有 data movement cost」。最佳化常先減少不必要 transfer/migration。
  • Q21：NCCL→RCCL 是 collective communication mapping；cuDNN→MIOpen；cuBLAS→rocBLAS/hipBLAS。
  • Q23：Porting 的順序是 build/run/correctness 先成立，再 profile/tune。
達標方式：30 題至少 27 題正確，而且每一題能講一句理由；若只是背 A/B/C/D，遇到改寫情境就容易失分。
Page 100 / 100Final Review

考前最後 60 分鐘，只看這一頁

0–15 min：五大 domain

Build & dependency
HIP fundamentals
Porting patterns
ROCm libraries awareness
Profiling & debugging fundamentals

15–30 min：API / library mapping

cudaMalloc → hipMalloc
cudaMemcpy → hipMemcpy
cudaDeviceSynchronize → hipDeviceSynchronize
cuBLAS → rocBLAS / hipBLAS
cuDNN → MIOpen
NCCL → RCCL
CUDA source migration → HIPIFY

30–45 min：工具

rocminfo → runtime/device info
amd-smi → GPU status/telemetry
ROCgdb → source debugging
rocprofv3 / ROCprofiler → profiling

45–60 min：手寫一次 flow

check environment
→ hipMalloc
→ H2D copy
→ calculate grid/block
→ launch kernel
→ error check / synchronize
→ D2H copy
→ validate
→ hipFree
→ profile hotspot
最後原則：遇到不確定題目，不要靠品牌名稱猜。先判斷它屬於 build、HIP、porting、library 還是 profiling/debugging，再選最直接符合需求的工具或概念。
你完成 100 頁後的能力目標：能獨立 build/run/debug 一個小型 HIP 程式、理解 CUDA→HIP migration、選對 ROCm library，並用 profiler 說明程式時間花在哪裡。這才是 Associate 準備的核心。
