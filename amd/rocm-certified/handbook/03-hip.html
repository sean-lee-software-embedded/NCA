Page 21 / 100HIP

HIP 的角色：portable C++ GPU programming

HIP（Heterogeneous-compute Interface for Portability）提供 C++ kernel language 與 runtime API。它的設計讓大量 CUDA-style code 能以相近概念在 AMD ROCm 環境使用，並支援 portability。

HIP 程式通常同時包含 host code 與 device kernel。Host 負責配置/傳輸 memory、launch kernel、處理結果；device kernel 則由 GPU threads 平行執行。

Host C++ hipMalloc → hipMemcpy → kernel launch → synchronize → hipMemcpy back → hipFree ↓ Device kernel
如果題目問 HIP 的主要目的，答「GPU programming model / portability」，而不是 profiler 或 deep learning library。
Page 22 / 100Hello HIP

第一支 HIP 程式：先會 compile/run

#include <hip/hip_runtime.h>
#include <cstdio>

__global__ void hello() {
    printf("Hello from GPU thread %d\n", threadIdx.x);
}

int main() {
    hipLaunchKernelGGL(hello, dim3(1), dim3(4), 0, 0);
    hipDeviceSynchronize();
    return 0;
}

編譯：

hipcc hello.cpp -o hello
./hello

__global__ 表示這是一個由 host launch、在 device 上執行的 kernel。這裡建立 1 block、4 threads。

GPU printf 是 debug/demo 用途。正式效能程式大量 printf 會嚴重拖慢執行。
Page 23 / 100Kernel Launch

看懂 hipLaunchKernelGGL 的每個參數

hipLaunchKernelGGL(
    vectorAdd,
    dim3(blocks),        // grid dimensions
    dim3(threads),       // block dimensions
    0,                   // dynamic shared memory bytes
    0,                   // stream (default stream)
    d_a, d_b, d_c, N);   // kernel arguments

前兩個 dim3 決定平行工作量；第三個參數是 dynamic shared memory；第四個是 stream。初學多用 0 代表沒有額外 dynamic shared memory、使用 default stream。

Launch configuration 是 host-side 行為。Kernel 裡讀取 blockIdx / threadIdx，host 則決定 grid/block dimension。
練習：N=1000，threads=256，blocks 應為 4。
Page 24 / 100Memory API

hipMalloc / hipMemcpy / hipFree 是必會三件組

float *d_a = nullptr;
size_t bytes = N * sizeof(float);
hipMalloc(&d_a, bytes);
hipMemcpy(d_a, h_a, bytes, hipMemcpyHostToDevice);
...
hipMemcpy(h_a, d_a, bytes, hipMemcpyDeviceToHost);
hipFree(d_a);

命名中的 d_ 常用來表示 device pointer，h_ 表示 host pointer；這不是 API 規定，但非常適合閱讀 code。

方向Kind
CPU → GPUhipMemcpyHostToDevice
GPU → CPUhipMemcpyDeviceToHost
GPU → GPUhipMemcpyDeviceToDevice
Pointer 所在 memory space 要搞清楚。把 host pointer 當 device pointer 傳給只接受 device memory 的 code 會造成 runtime error 或 invalid access。
Page 25 / 100Vector Add

完整 Vector Add：Associate 必做一次

#include <hip/hip_runtime.h>
#include <vector>
#include <iostream>

__global__ void add(const float* a,const float* b,float* c,int n){
    int i=blockIdx.x*blockDim.x+threadIdx.x;
    if(i<n) c[i]=a[i]+b[i];
}

int main(){
    const int N=1024;
    size_t bytes=N*sizeof(float);
    std::vector<float> a(N,1.0f),b(N,2.0f),c(N);
    float *da,*db,*dc;
    hipMalloc(&da,bytes); hipMalloc(&db,bytes); hipMalloc(&dc,bytes);
    hipMemcpy(da,a.data(),bytes,hipMemcpyHostToDevice);
    hipMemcpy(db,b.data(),bytes,hipMemcpyHostToDevice);
    int t=256,bk=(N+t-1)/t;
    hipLaunchKernelGGL(add,dim3(bk),dim3(t),0,0,da,db,dc,N);
    hipDeviceSynchronize();
    hipMemcpy(c.data(),dc,bytes,hipMemcpyDeviceToHost);
    std::cout<<c[0]<<"\n";
    hipFree(da);hipFree(db);hipFree(dc);
}
實作：把 N 改成 1003，確認仍正確。這可以驗證你真的理解 ceiling division + bounds check。
Page 26 / 100Synchronization

hipDeviceSynchronize 與 __syncthreads 不一樣

hipDeviceSynchronize() 是 host API，讓 host 等待此前 device work 完成。__syncthreads() 是 device-side block barrier，只同步同一 block 的 threads。

API在哪裡呼叫Scope
hipDeviceSynchronize()HostDevice work completion
__syncthreads()Kernel同一 block threads

同步太多會降低 concurrency，因此正確性先做對，再決定是否能改成 asynchronous workflow。

題目若問「host 要確保 kernel 完成後才讀結果」，可想到 device sync 或具同步語意的 copy；若問「block 內共享資料載入完才能計算」，想到 __syncthreads。
Page 27 / 100Error Handling

不要忽略 HIP runtime error

#define HIP_CHECK(call) do { \
  hipError_t e=(call); \
  if(e!=hipSuccess){ \
    fprintf(stderr,"HIP error: %s\n",hipGetErrorString(e)); \
    exit(1); \
  } \
} while(0)

HIP_CHECK(hipMalloc(&d, bytes));

Kernel launch 本身可能是 asynchronous，launch configuration error 可用 hipGetLastError() 檢查；真正執行期間的 illegal memory access 常在後續 synchronize 才浮現。

hipLaunchKernelGGL(...);
HIP_CHECK(hipGetLastError());
HIP_CHECK(hipDeviceSynchronize());
「程式沒有 crash」不等於沒有 GPU error。實作題應養成每個重要 runtime call 都檢查 error 的習慣。
Page 28 / 100Device Query

用 HIP API 查 device，而不只靠 shell 工具

int count=0;
hipGetDeviceCount(&count);
for(int i=0;i<count;i++){
    hipDeviceProp_t p{};
    hipGetDeviceProperties(&p,i);
    printf("%d: %s\n",i,p.name);
}

這類 API 可以讓應用程式依 device capability 決定行為。實務上若多 GPU，也可透過 hipSetDevice() 選擇目前 thread 使用的 device。

Shell-side rocminfo 與 programmatic hipGetDeviceProperties 都能取得裝置資訊，但使用情境不同。
Lab：印出 device name、totalGlobalMem、warpSize、maxThreadsPerBlock，並跟 rocminfo 對照。
Page 29 / 100Kernel Parameters

Kernel argument 與 pointer lifetime

Kernel arguments 可以是 scalar、struct value、device pointer 等。最常見錯誤是 pointer 指向的 memory 已被 free，或 host-side object 的 lifetime 已結束。

__global__ void saxpy(int n,float a,const float* x,float* y){
    int i=blockIdx.x*blockDim.x+threadIdx.x;
    if(i<n) y[i]=a*x[i]+y[i];
}

這裡 a 是 scalar value，x/y 則是指向 device memory 的 pointers。Host launch 時把 pointer 值當 argument 傳入。

不要在 kernel 完成前 hipFree 它正在使用的 buffer。Asynchronous execution 下 lifetime 特別重要。

HIP Fundamentals 最小能力清單

  1. 知道 __global__ kernel 在 device 執行。
  2. 會算 global index。
  3. 會算 blocks = ceil(N / threads)。
  4. 會 hipMalloc / hipMemcpy / hipFree。
  5. 會 launch kernel。
  6. 知道 host-side 與 block-side synchronization 差異。
  7. 會做 runtime error check。
  8. 能用 hipcc compile 一支小程式。
