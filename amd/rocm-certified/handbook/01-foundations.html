Chapter 1 · 認證流程與 ROCm 世界觀

先搞清楚「考什麼、ROCm 在整個 AMD 軟體堆疊的位置、與 CUDA 的關係」，後面學 HIP 才不會變成背 API。

Page 01 / 100Certification

ROCm Certified Associate 到底在驗證什麼？

AMD 將 Associate 的範圍定義為 Core AMD ROCm Software application development。也就是說，它不是硬體維修證照，也不是資料中心管理證照；核心是「你能否在 AMD GPU 上把應用程式建起來、移植、使用 ROCm library，並做基本 profiling / debugging」。

官方目前公開的五大 competency domains 是：Build and dependency management、HIP fundamentals、porting patterns、AMD ROCm libraries awareness、profiling and debugging fundamentals。這五項就是整本教材的骨架。

考試定位：官方 Agreement 明確寫 Associate 的 Evaluation Format 為 knowledge-based examination plus practical tasks。準備方式不能只背選擇題，至少要能看懂命令、程式碼與常見錯誤。
不要混淆：Academy 裡某一門 1-hour course 的 Quiz，不等於整張 Certification 的 final evaluation。Course completion 與 credential issuance 是不同層次。
自我檢查：用一句話回答：這張證照的核心是「ROCm application development」，還是「AMD GPU datacenter operations」？若回答前者，你抓到定位了。
Page 02 / 100Learning Flow

你現在看到的 AI Academy flow 怎麼解讀？

你在 Academy 看到的是 SCORM 課程結構：Module 1 Introduction、Module 2 Video: GPUs, ROCm, and HIP、Module 3 Quiz (15 questions)，右側顯示 Duration 1 Hours、Level Beginner、Projects 0 hands-on、Certificate No。這代表它是一個被追蹤完成度的 training course。

Academy training course ├─ Introduction ├─ Video / lesson └─ Quiz ↓ 後續 training / certification path ↓ AMD 指定的 Evaluation ↓ Knowledge exam + Practical tasks ↓ Credential / badge

tracking=True 的 SCORM URL 表示 Academy 會記錄 lesson completion。若後續 module 有鎖，通常要先完成前一段才解鎖。因此為了拿到完整 path，training course 不應直接跳過。

看到 Certificate: No 不代表「ROCm Certified Associate 沒證書」，只是這一個 Academy course 本身不發 course completion certificate。
週末策略：影片可加速播放，但要確保平台狀態是 Completed；Quiz 先自己做，再針對錯題回到教材，而不是只靠猜題。
Page 03 / 100ROCm

ROCm 是什麼？不是只有一個 compiler

ROCm 是 AMD 的開放 GPU compute software platform。實務上它包含 compiler、runtime、programming model、數學與 AI libraries、profiling/debugging 工具、framework integration 等多層元件。

Application / Framework ├─ PyTorch / JAX / TensorFlow ├─ MIOpen / rocBLAS / RCCL / rocFFT ... ├─ HIP runtime & HIP C++ ├─ Compiler / LLVM toolchain ├─ ROCr / driver-facing runtime components └─ AMD GPU hardware

把 ROCm 只記成「AMD 的 CUDA」有助於初學，但在考試或工作上要再精確一點：CUDA 是 NVIDIA 的整體軟體平台；HIP 則比較接近 CUDA C++ / CUDA Runtime 這一層的 programming model。ROCm 才是更大的 umbrella。

若題目問「哪個是 AMD 的 GPU software platform？」答案方向是 ROCm；若問「哪個 C++ programming model 用來撰寫 portable GPU kernel？」答案方向是 HIP。
常見錯誤：ROCm ≠ HIP。HIP 是 ROCm 生態中的重要 programming layer，但 ROCm 還包含很多 libraries 和 tools。
Page 04 / 100ROCm vs CUDA

用 NVIDIA 經驗快速建立 AMD mapping

對有 NVIDIA 基礎的人，最有效的方式不是重新從零背 AMD 名詞，而是建立 mapping。這些 mapping 是概念對照，不代表 API 100% 一樣。

NVIDIAAMD / ROCm用途
CUDA platformROCmGPU compute software ecosystem
CUDA C++ / runtimeHIPKernel 與 runtime API
nvcchipcc / amdclang++編譯
cuBLASrocBLAS / hipBLASBLAS
cuDNNMIOpenDeep learning primitives
NCCLRCCLMulti-GPU collective communication
nvidia-smiAMD SMIGPU management / telemetry
cuda-gdbROCgdbDebug

考試常見的不是問你「完整背出表格」，而是情境題。例如：某 CUDA 專案高度依賴 cuDNN，移植到 ROCm 時首先要研究哪個 library？答案方向就是 MIOpen。

口訣：DNN → MIOpen；Collective → RCCL；BLAS → rocBLAS；Kernel → HIP。
Page 05 / 100Software Stack

Framework、Library、HIP、Runtime：誰在呼叫誰？

高階 framework 並不代表「不需要 ROCm」。例如 PyTorch 在 AMD GPU 上執行時，底層仍透過 ROCm software stack 使用 GPU。Framework 讓使用者不用自己寫每個 kernel，但真正的計算會落到高度最佳化的 libraries 或 generated kernels。

Python model ↓ PyTorch ↓ ATen / backend integration ↓ MIOpen / rocBLAS / custom HIP kernels ↓ HIP runtime ↓ AMD GPU

在考試中，如果題目問「已經有成熟的 GEMM operation，要不要手刻 HIP kernel？」通常優先考慮 rocBLAS/hipBLAS，因為 domain-specific library 已針對硬體做最佳化。只有當現成 library 不符合需求時，才需要低階 custom HIP kernel。

Associate 不要求你成為 library implementer，但要知道「哪種問題該用哪個 ROCm library」，以及 library 與 HIP kernel 的抽象層次差異。
Page 06 / 100Instinct GPUs

為什麼教材一直提 AMD Instinct？

ROCm Certified Associate 的官方介紹明確把 hands-on workshops 放在 AMD Instinct GPU 上。Instinct 是 AMD 針對資料中心 AI / HPC 的 GPU 產品線，ROCm 是其主要軟體平台。

對 Associate 來說，不必死背每一代 MI300X、MI325X 等所有硬體規格，但要知道幾個軟體會用到的架構概念：Compute Unit (CU)、wavefront、HBM、matrix acceleration、device architecture target（如 gfx* 字串）等。

不要把硬體型號題準備過頭：這張 Associate 的官方 competency domains 沒有列「產品規格背誦」。比起背 HBM 幾 GB，更應該理解 HBM 是 device global memory，host-device transfer 與 on-device memory access 的成本不同。
實作前先會看：
rocminfo
amd-smi
hipcc --version
這三個動作可以快速回答「系統看不看得到 GPU？ROCm runtime 是否存在？compiler 是否可用？」

Page 08 / 100Practical Mindset

Practical task 要怎麼準備？

官方沒有公開 final practical task 的實際題目，因此最安全的準備方式是建立一套「最小可行 ROCm workflow」。看到陌生環境時，先確認裝置與 compiler；看到程式碼時，先 compile；錯誤先分 build-time / runtime / correctness / performance。

1. Environment rocminfo / amd-smi / hipcc --version 2. Build hipcc source.cpp -o app 3. Run ./app 4. Correctness compare expected output 5. Debug error check / ROCgdb 6. Profile rocprofv3 / profiler tools 7. Optimize memory access / occupancy / transfer / launch

這個流程比背 50 個命令更重要。因為 practical 題通常會把問題包成情境，你需要知道下一步做什麼。

練習：假設 hipcc 不存在，你第一反應不應該是改 kernel，而是確認 ROCm toolchain / PATH / installation。
Page 09 / 100English

考英文時，先掌握技術動詞

目前公開頁面沒有清楚承諾 final evaluation 的多語系，因此準備上應假設英文介面。技術英文最重要的不是文法，而是動詞與名詞配對。

英文看到時要聯想到
allocate配置 memory；hipMalloc
transfer / copyHost↔Device；hipMemcpy
launch啟動 kernel
synchronize等待/協調；device 或 block scope
profile量測時間、活動、counter，找 bottleneck
port / migrateCUDA→HIP / ROCm
dependencylibrary / version / include / link
occupancyCU 上 resident wavefront / threads 的資源利用概念
看到 “most appropriate”, “best first step”, “primarily” 這類字眼，要選最直接符合題意的工具，而不是所有「也做得到」的選項。
